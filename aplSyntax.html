APL Syntax

The syntax of the Aniol Programming Language for the Aniol 64/640 line of computers

Comments

Comments start with the '%' character and continue until the end of line.
Comments are ignored by the parser, and are not present in the tokenized file.

Types

Data is represented as a conjunction of 16-byte values.
Values may represent numerical data in the form of 16-bit signed integers or 16-bit pointers to arbitrary data structures.
In certain contexts, described in the documentation, only the lower 8-bits of a value may be significant, and the higher 8-bits are ignored.

Values

Numerical values are represented as 16-bit signed integer numbers or 16-bit pointers.
Numerical constants have the same format for both numbers and pointers, and can be either of the following:
  • Decimal numbers with a possible leading minus sign to indicate negative numbers, for example: 10, -1, 0, 35000
  • Hexadecimal numbers. Number format is '$' and exactly 4 hexadecimal digits from 0 to f. Only lowercase letters are allowed for digits a-f. Examples: $0000, $ffff, $abcd
  • Character literals are expressed using an apostrophe, for example: 'c, '#, '$. These are effectively 16-bit integers with the most significant byte equal to zero and the least significant byte equal to the given character's ASCII code.
Records are pointers to data structures in memory. Each element of a record is 2 bytes long.
Records are declared with the keyword REC, followed by the variable name and number of 2-byte elements, for example: 
REC x 10
Record declaration statically allocates memory for that record.
Record elements can be accessed with a dot operator, for example: 
x.5
x.(a+b)
Arrays are pointers to continuous areas of memory. Each element of an array is 2 bytes long.
Arrays are declared with the keyword ARR, followed by the variable name and number of 2-byte elements, for example: 
ARR a 10
Array declaration statically allocates memory for that array. Array elements can be accessed with a square bracket operator, for example: 
a[10]
a[i+j]
Nested array indices are not supported. 
a[b[i]]	%wrong
%use this instead:
j<-b[i]
a[j]
Note, arrays and records are internally identical. The ARR and REC keywords resolve to the same bytecode. Dot operator and square brackets can be used interchangeably.

String values are pointers to null-terminated strings in memory.
Each element (character) of a string is stored as one byte long.
Strings are declared with the keyword STR, followed by the variable name and number of characters, not counting the terminating null, for example: 

% allocates 11 bytes
STR s 10
String declaration statically allocates memory for that string. String elements can be accessed with a hash operator or a curly bracket operator, for example: 
s#10
s{i+j}
Reading a string element yields a 16-bit value, where only the lower 8 bits are significant and the higher 8 bits are zero Assigning a value to a string element requires a 16-bit value, where only the lower 8 bits are significant and the higher 8 bits are ignored and discarded. String constants are enclosed in double quotes: 
"test string"
Maximum length of string variables is 255 characters.
Maximum length of string literals is 127 characters.

Variables

Up to 128 named variables can be defined in any APL program.
Variable names begin with a lowercase letter.
Variable names may consist of upper or lowercase letters, decimal digits and the underscore '_' character.
Maximum length of a variable name is 8 characters.
Numerical variables are defined with first use.
All variables are global.

Statements

An APL program is a sequence of statements.
Statements are separated by newlines or the ':' statement separator character.
The following statements are supported:
  • Variable declaration
  • Variable assignment
  • Conditional statements
  • Loop statements
  • Procedure declarations
  • Procedure/function calls
  • Procedure return statement
  • STOP statement
  • END statement

Variable assignment

Assignment uses the variable name, followed by the assignment operator, followed by an expression. Assignment operator is '<-' Examples: 
x<-0
s<-"test"
a<-Abs(b)+1

Expressions

The following are allowed in expressions, listed in order of priority:
  1. Parentesis '(' and ')'
  2. Function calls. Functions are considered unary prefix operators.
  3. Record and Array index operator
  4. String index operator
  5. Unary operators: arithmetic negation '-' and logical negation '!'
  6. Multiplication-type operators: multiplication '*', division '/', modulo '\', conjuction '&'
  7. Addition-type operators: addition '+', subtraction '-', alternative '|'
  8. Comparison operators: equal '=', not equal '<>', greater or equal '>=', smaller or equal '<='
Note, the minus sign has three distinct meanings:
  1. In front of a numerical constant it forms part of the constant, for example -10
  2. In front of a variable it's a unary prefix operator for the arithmetic negation operation, for example -a
  3. Between two values (either constants or variables) it's a binary infix subtraction operator, for example 12-b

Keywords

Note: PROG and FUN keywords are reserved, but not used.
Other keywords are:
  • PROC: user-defined procedure declaration
  • END: indicates to the parser that processing of the source file should be stopped. Mandatory at the end of the program. File content beyond END is ignored.
  • RET: returns from a user-defined procedure
  • IF: conditional statement
  • ELSE: conditional statement
  • ENDIF: conditional statement
  • WHILE: begins loop statement
  • LOOP: ends a loop statement
  • FOR: begins loop statement
  • NEXT: ends a loop statement
  • ARR: array declaration
  • REC: record declaration
  • STR: string variable declaration
  • STOP: indicates to the interpreter to stop the execution. Causes the "Program terminated" message to be printed out, then the interpreter exists to the OS. If user-defined procedures are defined, place the procedures below the STOP statement. If no user-defined procedures are defined, the STOP statement is optional.
Additionally, the character ';' replaces the keyword ENDIF in case the last used keyword out of (IF, WHILE) was IF. Similarly, it replaces the keyword LOOP, if the last used keyword out of (IF, WHILE) was WHILE. So the following two snippets of code are equivalent: 
IF Cond 
	DoSth
ENDIF

%is equivalent to

IF Cond: DoSth;
Similarly, the following two snippets of code are equivalent: 
WHILE Cond
	DoSth
LOOP

%is equivalent to

WHILE Cond: DoSth;
FOR/NEXT loops are converted to WHILE/LOOP loops by the compiler. For example: 
FOR i<-0,i<10
NEXT

%is compiled to the same bytecode as: 

i<-0
WHILE i<10
	i<-i+1
NEXT

Function calls

All functions have exactly one parameter.
The parameter can be ommitted, in which case a zero is passed to the function. In this case the parentheses following the function call are mandatory
For some functions, the parameter is ignored.
The parameter can be placed in parenthesis, the parenthesis are optional if not otherwise required to establish operator priority.
Built-in functions can be called and their result used as part of an expression.
Alternatively, functions can be called like procedures, where the call is a complete statement and the result is discarded, for example: 
a<-Rnd(10)
a<-Rnd 10
c<-GetChar()
ioresult<-Open("file.txt")
Open("file.txt")

Built-in functions

Miscallenous functions:

  • Peek: returns a value from the memory address passed as parameter. Lower 8-bits are significant, upper 8-bits are 0.
  • Get: reads a value from the input port, the number of which is passed as parameter. For the parameter, lower 8-bits are significant, upper 8-bits are ignored. For the return value, Lower 8-bits are significant, upper 8-bits are 0.
Math functions:
  • Abs: absolute value of the parameter.
  • Rnd: pseudorandom value from 0 to parameter-1

String functions:
Len: length of string, not including the terminating null character

DOS functions:
Open: Loads a file from current directory on disk starting from address $c000. Returns I/O result
Save: Saves a file to current directory on disk. Returns I/O result
ChDir: Changes the current directory. Returns I/O result
Size: Returns the size, in bytes, of the currently opened file. The parameter is ignored.
MkDir: Creates a directory. Returns I/O result
RmDir: Removes a directory. Returns I/O result
DosErr: Returns the status of the last I/O operation. 0 indicates success. Parameter indicates whether any error should be cleared.
Delete: Deletes a file. Returns I/O result
Touch: Creates an empty file. Returns I/O result
Exists: Returns a value indicating whether the specified file exists in the current directory.

All the DOS functions that return I/O status of the operation also they set an internal variable to the same status. The value of the variable is accessible by using the DosErr function. This means that the following two snippets of code are functionally equivalent: 

ioresult<-Open("test.txt")
%is equivalent to
Open("test.txt")
ioresult<-DosErr()

Procedure declarations

User-defined procedures are declared with a header consisting of the PROC keyword, followed by procedure name.
Procedure names start with an uppercase letter.
Procedure names may consist of upper or lowercase letters, decimal digits and the underscore '_' character.
Keywords can't be used as procedure names.
Maximum length of a procedure name is 8 characters.
Following the procedure header, any statements are allowed. They form the procedure body.
The procedure terminates with the RET statement.

Procedure calls

Procedures are called by stating their names.
Built-in procedures can be called with a defined number of parameters. Parameters are separated by commas.
User-defined procedures cannot have parameters. Use global variables to pass values instead.
Examples: 
GotoXY x, y+1
MyProc
